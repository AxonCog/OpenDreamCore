## 一、五分钟出活：你的第一个附属

目标：做一个附属，给服务器附带一套"暗金"主题 + 一个打开商店页面的命令。

**第一步**，建插件工程，`plugin.yml` 声明软依赖：

```yaml
name: MyAddon
version: 1.0
main: com.example.myaddon.MyAddon
depend: [OpenDreamCore]     # 硬依赖；用 softpend 则参考第四节做降级
```

**第二步**，`src/main/resources/themes/gold.yml` 放一份主题（语法见《YAML语法.md》§12）：

```yaml
vars:
  gold: "#FFD54F"

".rpg_panel":
  background: {color: "#1A1408EE", radius: 8}
  borderColor: "{gold}"
```

**第三步**，主类注册主题：

```java
public class MyAddon extends JavaPlugin {
    @Override
    public void onEnable() {
        // 从 jar 资源里读主题并登记——重复注册同名自动覆盖，升级无忧
        String yaml = new String(getResource("themes/gold.yml").readAllBytes());
        OpenDreamCoreAPI.theme().register("gold", yaml);
        getLogger().info("暗金主题已就绪");
    }
}
```

**第四步**，页面里就能用了。任何页面头部写 `theme: gold`，
或元素挂 `class: rpg_panel`，皮肤即刻生效。

完成。这就是附属开发的全部门槛。



## 二、API 全家福

所有 API 通过 `OpenDreamCoreAPI` 门面访问，单例模式，插件未加载时安全返回默认值：

| 入口 | 干什么 | 常用方法 |
|---|---|---|
| `gui()` | 页面 | open / openSubPage / close / setVariable / setElementProp |
| `hud()` | HUD 与世界 UI | showBossBar / 名牌 / 物品提示 / 音乐 / 屏幕特效 |
| `element()` | 元素操作 | 显隐 / 属性修改（点路径） |
| `container()` | 容器 | 读写槽位物品 / 光标管理 / 重同步 |
| `tooltip()` | 提示 | 运行时注册/移除元素提示 |
| `script()` | 脚本扩展 | 注册自定义 DreamLang 方法 |
| `title()` | 窗口标题 | 打字机/轮播/随机标题下发 |
| `theme()` | **主题（本指南主角）** | register / unregister / reloadFromPluginDir |

事件监听走 Bukkit 事件总线（`OdcEvents.ButtonEvent` 等），`@EventHandler` 直接挂。



## 三、ThemeAPI 深度指南

### 3.1 方法一览

```java
ThemeAPI theme = OpenDreamCoreAPI.theme();

boolean register(String name, String yamlText)   // 注册/覆盖同名主题
boolean unregister(String name)                  // 注销（引用它的页面回退 default）
Set<String> names()                              // 已注册清单
boolean exists(String name)                      // 存在性检查
int loadFromDir(Path dir)                        // 从目录批量加载（递归）
int reloadFromPluginDir(Plugin addon)            // 重载 dataFolder/themes/
List<String> resolveChain(String pageThemeName)  // 调试：看 theme: 声明实际命中谁
```

### 3.2 推荐的工程姿势

**主题文件放哪？** 两种模式任选：

- **jar 内置**（推荐给"产品型"附属）：资源目录带 `themes/gold.yml`，onEnable 时读出来注册。
  用户无感知，升级即更新。
- **数据目录托管**（推荐给"平台型"附属）：`dataFolder/themes/` 让用户自己丢文件，
  onEnable 调 `reloadFromPluginDir(this)`，再配个 `theme reload` 子命令。

**多主题叠加怎么玩？** 页面写 `theme: default,myaddon_gold`：
先套 default 兜底，你的 gold 只覆盖你关心的属性。这就是附属之间互不打架的关键，
**只声明你独有的部分，别整包复写**。

**版本升级**：同名 register 就是覆盖。建议主题名带上命名空间
（`myaddon_gold` 而不是 `gold`），避免和其他附属撞车。

### 3.3 调试技巧

```java
// 页面写了 theme: default,myaddon_gold，实际命中了什么？
getLogger().info("命中链: " + OpenDreamCoreAPI.theme().resolveChain("default,myaddon_gold"));
// → [default, myaddon_gold]
```

规则没生效时按这个顺序查：主题注册了吗（names()）→ 页面 theme 名拼对了吗 →
class 拼写一致吗（区分大小写）→ 属性是不是被内联压住了（内联永远赢）。



## 四、主题分发模型（重要）

先把架构事实摆清楚：**主题在客户端构建页面时生效**，服务端下发的只是页面 YAML 源文。

所以分发路径分三条，各有适用场景：

| 场景 | 做法 |
|---|---|
| 单机玩家自用 | 手动放 `OpenDreamCore/themes/`，完事 |
| 服务器全员统一 | **资源云下发**：把 theme.yml 放进云资源目录，玩家进服自动同步到本地 themes/ |
| 附属自带皮肤 | 本 API 注册（服务端库）+ 引导玩家安装客户端侧文件，或配合资源云 |

为什么服务端注册不能直接"推"到客户端？因为页面构建发生在客户端，
服务端的主题库只在服务端自己编译/校验页面时使用。
跨端同步是资源云的职责，职责分离，各自简单。



## 五、脚本扩展：给 DreamLang 添加新方法

附属最常见的需求之一：让页面作者能调用你的业务能力。

```java
public class ShopMethods extends JavaPlugin {
    @Override
    public void onEnable() {
        ScriptAPI.register("MyShop", "购买", args -> {
            // args 是页面脚本传来的参数列表
            String itemId = String.valueOf(args[0]);
            int count = Integer.parseInt(String.valueOf(args[1]));
            boolean ok = doPurchase(itemId, count);
            return ok ? "购买成功" : "余额不足";
        });
    }
}
```

页面脚本里即可调用：

```yaml
buy_btn:
  actions:
    click: "Toast.显示(MyShop.购买('diamond', 1))"
```

命名空间（第一个参数）会挂在方法名前面，天然隔离不同附属的同名方法。



## 六、打包与依赖声明

`build.gradle`：

```gradle
repositories {
    mavenCentral()
    // OpenDreamCore 发布仓库（占位，按实际发布渠道填写）
}

dependencies {
    compileOnly 'com.opendreamcore:opendreamcore-plugin:<版本>'
}
```

要点：

- **compileOnly**，不要 shadow 进你的 jar，宿主已经提供了全部类
- `plugin.yml` 里 `depend: [OpenDreamCore]` 或 `softdepend`（软依赖时记得判空）
- 所有 API 调用在插件未加载时安全返回 false/null/null 集合，可以放心写在 onEnable
